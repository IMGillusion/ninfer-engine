VHDX 缩容封顶执行方案（runbook 已设计完成）

目标状态：ext4 文件系统 1007G→100G，VHDX 虚拟容量 1007G→110G（物理封顶，永不再增长），文件压实到 ~90G。停机窗口预计 30-70 分钟，需要你在场（UAC + 确认节点）。

━━ 执行流程 ━━

【窗口前准备（你在场之前我做完）】
1. 备份 3 个 docker volumes（1.8G）tar 导出到 E:/vhdx-cap-backup/
2. 从 alpine 容器提取 e2fsprogs 工具链备用 tarball（防 docker-desktop VM 缺 resize2fs 的兜底）
3. 写好全部脚本到 F:/Docker/cap_vhdx/：backup.ps1、shrink_fs.sh、resize_vhdx.ps1（virtdisk P/Invoke）、compact.txt（diskpart）、verify.ps1
4. 停 watchdog（防中途误重启）

【窗口内（你确认后执行）】
5. 备份 volumes → E:（约 2 分钟）
6. 优雅停 Docker Desktop（先 docker stop ninfer → 退出 Docker Desktop → wsl --shutdown；ext4 若有脏由 e2fsck 修复，属设计内）
7. 缩文件系统：wsl --mount --vhd --bare --distribution docker-desktop 把盘挂为裸设备 → 决策树：优先用 docker-desktop VM 自带的 e2fsprogs（它自己格式化过这块盘，大概率有）→ 若缺失，用准备的工具链 tarball → e2fsck -f 强制校验 → resize2fs /dev/sdX 100G（最耗时，10-40 分钟）→ wsl --unmount
8. 缩虚拟容量：ResizeVirtualDisk（P/Invoke 脚本）1007G → 110G；若 API 拒绝缩（极少见），回退方案=仅 compact（文件仍回 ~90G，封顶改用观察模式并向你如实汇报）
9. diskpart compact vdisk：文件 105.55G → ~90G
10. 重启 Docker Desktop → 容器自动拉起 → 验证：索引 fast-path dropped=0、锚点链冒烟、F: 空闲与 VHDX 大小核对
11. 重启 watchdog；恢复巡检

【回滚与安全网】
- volumes 有 tar 备份；L3 缓存可冷重建（索引校验 6.5s + 缓存数小时回血）；镜像可重拉
- e2fsck 前后各跑一次；resize2fs 中断的最坏情况 = 盘损坏 → 用备份+重建恢复
- 若未来需要扩回：同一 P/Invoke 脚本反向执行（在线扩容，非破坏性，1 分钟）

【上限后的行为】
- 写满 110G = VM 收 ENOSPC 报错（不再悄悄扩文件）；74G L3 固定几何自滚动 + docker 层已剪，余量 20G+ 正常到不了
- 哨兵体系照常：60s 排队死线 + 300s 物化哨兵继续兜底；若封顶后仍出现卡死 = Windows 层成因坐实，届时上熔断器
